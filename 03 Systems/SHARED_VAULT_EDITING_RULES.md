# Shared Vault Editing Rules

## Purpose
Keep the shared Obsidian vault clean when multiple agents use it.

## Rules
1. Update existing notes first
2. One master note per project
3. Use clear filenames
4. Put temporary fragments in `00 Inbox` or `07 Scratch`
5. Promote high-signal notes into the right permanent folder
6. Do not leave final decisions only in chat
7. If code changed, GitHub still needs the commit history
8. If a structure change is made, document it in `03 Systems`

## Default folder intent
- `00 Inbox` -> quick capture
- `01 Daily` -> daily logs
- `02 Projects` -> active project truth
- `03 Systems` -> operating rules/workflows
- `04 Reference` -> reusable knowledge/templates
- `05 Decisions` -> major decision records
- `06 Reviews` -> audits/retros/postmortems
- `07 Scratch` -> temporary working space
